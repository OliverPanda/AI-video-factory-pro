## 4. 本轮新增修复

### 4.1 审片时间线 clips 消费缺陷

- 问题：后端 `/api/runs/:id/review/clips` 返回 grouped clips 对象，前端按数组直接 `.map()`，会导致审片页加载失败
- 修复：
  - `views/src/lib/workbench.ts`
  - `tests/workbench/reviewClips.frontend.test.mjs`
- 结果：新增回归测试先失败后通过

### 4.2 编辑后回读优先级修正

- 问题：shot / character / scene / voice 保存后，重新打开同一 run 时，前端可能优先展示旧 snapshot 而非 `episode.json` 最新值
- 修复：
  - `views/src/lib/workbench.ts`
- 处理方式：
  - `shots` 优先读取 episode 级 detail
  - `characters / scenes / voices` 优先读取 episode detail，snapshot 作为 fallback
- 自动化证明：
  - `tests/workbench/workbenchProject.frontend.test.mjs`

### 4.3 DramaDetail 失效 run 参数校正

- 问题：URL 中 `run` 失效但 `episode/script` 仍有效时，页面能回退显示剧集，但本地 `selectedRunId` 不会同步纠正，后续动作可能继续指向失效 run
- 修复：
  - `views/src/pages/DramaDetail.tsx`

### 4.4 审片过滤后选中 clip 重置

- 问题：review 页过滤条件变化或刷新后，如果当前 clip 消失，原逻辑会回退到 `clips[0]`，可能落到当前过滤结果外
- 修复：
  - `views/src/components/review/PreviewReviewPage.tsx`
- 自动化证明：
  - `views/src/components/review/reviewSelection.ts`
  - `tests/workbench/workbenchProject.frontend.test.mjs`

### 4.5 审片播放器失败态恢复入口

- 问题：计划要求视频加载失败时，播放器区域显示友好提示，并提供 Artifact 恢复入口；此前页面缺少该入口
- 修复：
  - `views/src/components/review/PreviewPlayerPanel.tsx`
  - `views/src/components/review/PreviewPlayerPanelState.ts`
- 自动化证明：
  - `tests/workbench/previewPlayerPanel.frontend.test.mjs`

### 4.6 Storyboard emotion 字段闭环

- 问题：M3 计划点名的 shot `emotion` 字段此前未纳入真实 storyboard 读取与 patch 保存链路
- 修复：
  - `views/src/lib/workbench.ts`
  - `views/src/pages/Editor.tsx`
- 自动化证明：
  - `tests/workbench/workbenchProject.frontend.test.mjs`

### 4.7 Editor 失败回滚粒度修正

- 问题：分镜页此前保存失败时会整条 shot 回滚，可能覆盖同一 shot 上后续已编辑字段
- 修复：
  - `views/src/pages/Editor.tsx`
  - `views/src/pages/editorState.ts`
- 自动化证明：
  - `tests/workbench/editorState.frontend.test.mjs`

### 4.8 Editor scene 与 sceneId 同步

- 问题：用户编辑 `scene` 文本后，右侧场景上下文可能仍绑定旧 `sceneId`
- 修复：
  - `views/src/pages/Editor.tsx`
  - `views/src/pages/editorState.ts`
- 自动化证明：
  - `tests/workbench/editorState.frontend.test.mjs`

### 4.9 review/video 绝对 finalVideoRef 兼容

- 问题：真实历史 run 的 `edit-task-pack.json.finalVideoRef` 指向临时绝对路径，旧实现会因“路径不在 run 目录内”直接返回 `400`
- 修复：
  - `src/workbench/http/router.js`
  - `tests/workbench/workbenchServer.test.js`
- 行为：
  - 对受信任根目录内、且文件名为 `final-video.mp4` 的历史绝对路径允许读取
  - 任意其他绝对路径与目录穿越仍继续拒绝
- 自动化证明：
  - `GET /api/runs/:runId/review/video serves trusted absolute temp finalVideoRef`
  - `GET /api/runs/:runId/review/video rejects absolute finalVideoRef outside run directory`
  - `GET /api/runs/:runId/review/video rejects parent traversal finalVideoRef outside run directory`

### 4.10 storyboard 按 runId 精确回捞真实 artifact

- 问题：Editor 带 `runId` 打开时，后端 storyboard API 仍按 `projectId/scriptId/episodeId` 选择同分集最新 run，导致真实 artifact 错配，页面返回 `Episode not found`
- 修复：
  - `src/workbench/http/router.js`
  - `views/src/lib/workbench.ts`
  - `views/src/hooks/useWorkbench.ts`
  - `views/src/pages/Editor.tsx`
  - `tests/workbench/workbenchServer.test.js`
- 行为：
  - storyboard / episode / shot PUT 路由支持 `?runId=...`
  - 后端优先按 `runId` 精确命中 artifact run
  - 当真实 run 缺 `episode.json` 时，可用 `shot-packages.json` 与 `dialogue-normalized.json` 合成最小 storyboard payload
- 自动化证明：
  - `GET storyboard prefers requested runId artifact payload when project store episode is missing`
- 真实验证：
  - `http://127.0.0.1:4311/editor?...run_job_regen_reanchor_20260617112039769_efa6152d` 已成功打开

### 4.11 episode detail 角色双副本回读同步

- 问题：`PUT /api/projects/:projectId/scripts/:scriptId/episodes/:episodeId/characters/:charId` 更新后，同一次 `GET /api/projects/:projectId/scripts/:scriptId/episodes/:episodeId` 返回中，`episodeCharacters` 已更新，但 `characters` 副本可能仍保留旧值，导致前端回读不一致
- 修复：
  - `src/workbench/http/router.js`
  - `tests/workbench/workbenchServer.test.js`
- 行为：
  - character PUT 后，会同步更新 `episodeCharacters` / `characters` 两个角色副本
  - episode detail 回读不再出现“一个新值、一个旧值”的状态漂移
- 自动化证明：
  - `PUT /api/projects/:projectId/scripts/:scriptId/episodes/:episodeId/characters/:charId keeps episode detail character copies in sync`
