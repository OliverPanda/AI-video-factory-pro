# 2026-04-20 一致性评分与场景化 QA 包容度设计

## 目标

为当前短剧生产线设计一套更贴近行业主流的一致性策略，使系统从“统一阈值 + 后验补救”为主，升级到：

- `先锁身份，再放变化`
- `主角严格，复杂镜头适度放宽`
- `分数负责提示风险，规则负责决定放行`
- `失败镜头优先回锚重生，而不是沿着漂移结果继续修`

本设计的目标不是承诺“所有镜头一致性都保底 8 分”，而是更现实地做到：

- 提高主角和关键角色镜头的一致性下限
- 减少复杂动作镜头被统一阈值误杀
- 让 QA 更像业务决策层，而不是单一打分器
- 在不额外误烧视频成本的前提下，把问题尽早拦在视频前

## 背景与问题

从当前项目实现和最近一次《致命抉择》真实跑测来看，当前一致性链路已经具备以下能力：

- `CharacterBible`、`negativeDriftTokens` 等角色锚点字段
- `Consistency Checker` 输出评分、漂移标签、`needsRegeneration`
- `Director` 在一致性不达标时触发自动重生图
- `--stop-before-video` 下已能跳过自动补生图，避免继续烧钱

但当前策略仍然有几个明显问题：

### 1. 更偏“先生成，再靠 QA 抓漂移”

当前主流程里，一致性更多还是后验纠偏层，而不是生成前的强约束层。

这会导致：

- 角色身份锚点不够硬
- 漂移往往在图已经生成后才暴露
- 后续只能靠补图兜底

### 2. 统一阈值不适合短剧

当前一致性检查更接近：

- 统一分数阈值
- 低于阈值就加入 `needsRegeneration`

这种方式对不同场景不公平：

- 单人近景、主角首亮相，本来应该严格
- 动作戏、远景、低光、遮挡镜头，本来就更难

如果所有镜头都按一把尺子量，就会同时出现：

- `误杀`
  - 复杂镜头本来可用，却因为天生难度高被拦掉
- `漏放`
  - 关键身份镜头本该更严格，却被统一阈值放过去

### 3. 自动重生图是补救层，不是主控制层

当前 `Consistency Checker -> Director -> regenerateImage(...)` 的闭环能救火，但它更像补救策略。

行业主流做法更偏：

- 先准备主参考资产
- 先锁住不可漂移的身份元素
- 再让镜头、姿势、运镜和场景变化

### 4. 当前评分语义不够“业务化”

当前一致性分数确实有价值，但“分数低”不等于“必须挡住”。

例如：

- 主角关键特写 7.8 分，可能已经该 `warn` 或 `block`
- 配角低光动作远景 7.0 分，未必需要挡住

因此，单一总分不适合作为唯一决策源。

## 行业参考与取舍

结合主流官方和社区经验，可以归纳为一条共识：

> 不是在“强一致性”和“电影感”之间二选一，而是先锁身份，再放变化。

对当前项目最值得借鉴的部分：

- `主参考资产优先`
  - 角色先有稳定参考，再做剧情镜头
- `回锚重生`
  - 漂了以后回到主参考重生，而不是沿着漂掉的结果继续修
- `分层锁定`
  - 锁死脸、发型、服装轮廓、主配色
  - 放开姿势、镜头、景别、光线变化
- `主角与配角分级`
  - 主角更严，配角稍松
- `复杂镜头包容度更高`
  - 但只放宽软漂移，不放宽身份硬错误

不直接照搬的部分：

- 官方 showcase 偏展示型，不一定适合低成本流水线生产
- 社区很多方法默认人工挑图、人工回锚，而本项目需要规则化、可自动执行的策略

## 设计决策

本设计采用：

- `双轴 QA 模型`
  - 角色重要性轴
  - 镜头复杂度轴
- `硬约束 + 软约束` 双层判定
- `pass / warn / block` 三段式结果
- `主参考回锚重生` 作为主要修复策略

最终策略口径：

> 主角严格，复杂镜头适度放宽；分数做风险信号，规则做放行决策。

## 方案对比

### 方案 A：全局统一阈值 + 少量白名单

优点：

- 最容易落地
- 改动小

缺点：

- 补丁化严重
- 很难解释为什么某镜头放过、某镜头被挡
- 长期不可维护

### 方案 B：按镜头类型分级 QA

优点：

- 比统一阈值合理得多
- 能部分解决动作戏误杀问题

缺点：

- 没有体现主角和配角的重要性差异
- 仍然不够贴合业务优先级

### 方案 C：按角色等级 × 场景类型的双轴 QA

优点：

- 最符合短剧业务
- 能表达“主角关键镜头更严、复杂镜头适度放宽”
- 更接近可长期演进的产品规则

缺点：

- 规则设计和测试成本更高

### 最终选择

选择 `方案 C：双轴 QA`。

原因：

- 当前问题不只是阈值高低，而是镜头天然难度不同、角色业务重要性不同
- 对短剧而言，主角身份稳定性远高于配角和复杂远景镜头
- 双轴模型最适合承接后续的 prompt 锁定、QA 判定和回锚重生闭环

## 核心架构

建议把一致性策略拆成 4 层：

### 1. 角色主参考层

职责：

- 为主角和关键配角建立稳定角色身份资产
- 作为项目级唯一真相源

关键原则：

- 不直接用剧情镜头充当角色定义
- 先有“干净、可复用”的角色主参考

### 2. 生成前约束层

职责：

- Prompt 生成时按角色等级和镜头类型注入不同强度的身份锁

关键原则：

- 主角与关键镜头要更强 identity block
- 配角和复杂镜头可以适度放宽表现细节

### 3. 生成后 QA 判定层

职责：

- 输出分数
- 输出硬错误、软风险
- 形成 `pass / warn / block`

关键原则：

- 分数不是唯一决策条件
- 需要显式区分“身份错误”和“表现波动”

### 4. 回锚重生层

职责：

- 被判 `block` 或高风险的镜头优先回到主参考重生

关键原则：

- 不沿着已经漂掉的图继续修
- 保证修复策略能真正减少身份漂移累积

## 核心对象

建议引入或强化以下运行时概念：

### `character_priority`

取值：

- `lead`
- `support`
- `minor`

作用：

- 表达角色业务重要性

### `shot_consistency_class`

取值：

- `anchor`
- `standard`
- `complex`

作用：

- 表达镜头一致性控制难度

### `identity_hard_rules`

作用：

- 存放不能放宽的身份规则

### `identity_soft_rules`

作用：

- 存放可按场景放宽的细节规则

### `regen_strategy`

建议取值：

- `none`
- `prompt_tighten`
- `reanchor_regenerate`

作用：

- 表达镜头不达标后的修复路径

## 镜头与角色分级

### 角色等级

#### `lead`

- 主角
- 核心叙事角色
- 用户最敏感的角色

#### `support`

- 重要配角
- 反复出现的次主角色

#### `minor`

- 次要角色
- 群像中的非关键角色

### 镜头复杂度

#### `anchor`

适用场景：

- 主角首亮相
- 角色定妆镜头
- 单人近景
- 关键对白特写

特征：

- 角色身份展示价值高
- 理应最稳

#### `standard`

适用场景：

- 普通双人对话
- 中景叙事镜头
- 低动作镜头

#### `complex`

适用场景：

- 动作戏
- 追逐
- 打斗
- 背身
- 低光
- 遮挡
- 远景群像

特征：

- 天然更容易发生细节漂移
- 不适合用 `anchor` 的标准硬卡

## 双轴 QA 策略

建议组合规则如下：

- `lead + anchor`
  - 最严
- `lead + standard`
  - 严
- `lead + complex`
  - 中严
- `support + standard`
  - 中
- `support + complex`
  - 中宽
- `minor + complex`
  - 最宽

这不是简单地调一个分数，而是表达：

- 谁更重要
- 这个镜头天然有多难

## QA 判定模型

### 三段式结果

建议统一为：

- `pass`
  - 可继续
- `warn`
  - 可继续，但需要记风险
- `block`
  - 不可继续，必须先处理

### 分数的职责

分数只负责：

- 表达风险强弱
- 帮助排序和聚合
- 帮助生成修复建议

分数不负责：

- 单独决定镜头生死

### 硬约束

以下问题建议直接进入 `block` 判定：

- 角色串人
- 主角脸型明显变化
- 主角发型主轮廓明显变化
- 主角服装主轮廓漂移
- 标志性武器或身份道具错误
- 同一角色被拆成两个名字体系
- 关键参考图缺失，形成 `missing_reference_stack`

### 软约束

以下问题建议优先进入 `warn`：

- 发丝凌乱程度不同
- 血迹深浅不同
- 低光下五官不够清
- 动作镜头中的局部姿态不稳
- 配角在复杂镜头中的轻度轮廓漂移
- 局部光影造成的轻微配色波动

## 建议阈值

以下阈值不是绝对保底线，而是建议初版控制线：

- `lead + anchor`
  - 低于 `8.5` 至少 `warn`
- `lead + standard`
  - 低于 `8.0` `warn`
- `lead + complex`
  - 低于 `7.2 ~ 7.5` `warn`
- `support + standard`
  - 低于 `7.5` `warn`
- `support + complex`
  - 低于 `7.0` `warn`
- `minor + complex`
  - 仅在明显身份错误时升级为 `warn / block`

注意：

- 这些阈值只用于风险提示和优先级排序
- 是否 `block`，仍由硬约束决定

## 对当前项目的直接调整建议

### 1. 先补角色主参考资产

目标：

- 让 `CharacterBible` 真正拥有可用参考图资产
- 不再只停留在文本描述层

建议：

- 每个主要角色至少一套稳定三视图或定妆主参考
- 保证服装、发型、主配色、年龄感明确

### 2. Prompt 锁定强度按角色和镜头分层

目标：

- 主角和关键镜头更强 identity block
- 配角和复杂镜头适度减少过度细节束缚

建议：

- `lead + anchor`
  - 强 identity token
  - 强 negative drift token
- `complex`
  - 放宽软细节，但保留硬身份锚点

### 3. QA 从“单分数阈值”升级到“规则 + 分数”

目标：

- 让 QA 结果更符合业务需求

建议：

- 输出 `hard_fail_reasons`
- 输出 `soft_risk_tags`
- 输出 `recommended_action`

### 4. 重生成优先走回锚策略

目标：

- 避免越修越漂

建议：

- 对 `block` 镜头优先使用主参考回锚重生
- 对 `warn` 镜头先尝试 prompt tighten

## 预期收益

如果按本设计落地，预期收益包括：

- 主角和关键角色更稳
- 复杂动作镜头被误杀的概率下降
- QA 输出更业务化、更可解释
- 一致性分布更健康，不再大量集中在 `6 ~ 7`
- 问题更早暴露在视频前，而不是等到视频成本已经发生后才发现

## 非目标

本设计不追求以下结果：

- 承诺所有镜头一致性保底 `8`
- 完全取消人工审阅
- 用单一 Prompt 技巧解决所有身份漂移问题
- 一次性解决所有视频时序级一致性问题

## 风险与代价

### 1. 主角镜头可能更保守

为了稳住身份，部分镜头的视觉变化感可能会下降。

### 2. 角色主参考资产建设有成本

如果没有稳定主参考，本设计收益会打折。

### 3. 规则复杂度会上升

需要同步补文档、测试和 QA 审计字段。

### 4. 镜头分类质量会影响结果

如果 `anchor / standard / complex` 分级不准，可能导致：

- 该严不严
- 该松不松

## 落地顺序建议

建议按以下顺序实施：

1. 补角色主参考资产
2. 新增镜头复杂度分级
3. 新增角色等级配置
4. 升级 QA 为三段式 + 双轴阈值
5. 引入回锚重生成策略

## 最终建议

对于当前项目，最合适的路线不是继续微调一个统一一致性阈值，而是：

> 采用“主角严格、复杂镜头适度放宽”的双轴 QA 方案，并把一致性从单纯后验补救，升级为“主参考资产 + 生成前锁定 + 生成后业务判定 + 回锚重生”的完整闭环。

这条路线既符合短剧场景，也最接近当前行业内真正可持续提升一致性的主流做法。
