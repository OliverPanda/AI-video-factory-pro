# 2026-04-20 《致命抉择》各步骤最终 Prompt 清单

本文只记录当前仓库实现里，**各步骤最终喂给模型/Provider 的 prompt 或 prompt block**。  
不展开流程解释，目的是方便直接审阅、排障和对齐口径。

## 总览

| 步骤 | 最终输入形态 | 说明 |
| --- | --- | --- |
| Script Parser | 无 prompt | 纯解析，不调用 LLM |
| Character Registry | 文本 prompt | 角色视觉档案生成 |
| Character Ref Sheet | 文本 prompt | 角色三视图/转面图 |
| Prompt Engineer | 文本 prompt + 本地增强 | 分镜生图 prompt |
| Consistency Checker | 文本 prompt | 角色一致性 QA |
| Director Pack | 结构化 pack | 不走自然语言 prompt |
| Motion Planner | 结构化 plan | 不走自然语言 prompt |
| Performance Planner | 结构化 plan | 不走自然语言 prompt |
| Video Router | 结构化 request hints | 只做路由，不产出自然语言 prompt |
| Seedance Prompt Agent | 结构化 prompt blocks | 单镜头/sequence 的最终 provider 输入核心 |
| Preflight QA | 结构化重写 blocks | 发现风险后补 block |
| Bridge Shot Router | 文本 directives | bridge clip 的最终输入 |
| Action Sequence Router | 结构化 package | sequence clip 的最终输入 |

## 1. 角色建档

来源：`src/agents/characterRegistry.js`

### System Prompt

核心内容是：

- 你是专业的漫剧角色设计师
- 负责提取角色可视化特征
- 输出英文视觉描述词
- 关键词要匹配写实或 3D 风格

### User Prompt

输入结构大致是：

```text
<剧本背景>
{scriptContext}
</剧本背景>

<角色列表>
- 角色A（女，成年）
- 角色B（男，成年）
</角色列表>

<视觉风格>
写实摄影风格 / 3D渲染风格
</视觉风格>
```

### 最终输出 JSON

```json
{
  "characters": [
    {
      "name": "角色名",
      "gender": "male/female",
      "age": "年龄描述",
      "visualDescription": "英文外观描述",
      "basePromptTokens": "核心提示词",
      "personality": "性格特点"
    }
  ]
}
```

## 2. 角色三视图

来源：`src/llm/prompts/promptEngineering.js`

### 最终 Prompt

实际会拼成下面这类英文 prompt：

```text
one single male/female person, {identity}
character turnaround sheet, 3 views side by side: front | side profile | back
full body head to toe, standing pose, centered in each panel, pure white seamless studio background
same person same outfit in all 3 views, equal spacing
isolated subject only, no props, no furniture, no environment objects, no architecture, no background structures
photorealistic, studio photo / 3D render, Pixar style, character model sheet
high quality, sharp, even lighting
```

### 负面词

```text
photograph, blurry, low quality, watermark, text, labels, props, furniture, ladder, stairs, rack, pillar, walls, background objects, environment
```

### 关键点

- 这里的身份词来自 `basePromptTokens`
- 会主动过滤楼梯、货架、柱子、墙等场景词
- 目标是纯白底、纯角色、纯三视图

## 3. 分镜图 Prompt Engineer

来源：`src/llm/prompts/promptEngineering.js` + `src/agents/promptEngineer.js`

### System Prompt

核心内容：

- 专业 AI 图像提示词工程师
- 面向中文漫剧场景生成英文 prompt
- 主体优先
- 风格一致
- 情绪要靠光线、色调、构图传达
- 输出双语字段

### User Prompt

会把以下信息喂给 LLM：

```text
<分镜信息>
场景：...
出场角色：...
动作：...
情绪：...
镜头：...
</分镜信息>

<连续性约束>
承接镜头：...
场景光照：...
镜头轴线：...
道具状态：...
连续风险：...
</连续性约束>

<角色视觉档案>
角色名：visualDescription；identity=...；avoid=...
</角色视觉档案>

<风格>
写实摄影风格 / 3D渲染风格
</风格>
```

### LLM 输出 contract

```json
{
  "image_prompt_en": "英文正向 prompt",
  "negative_prompt_en": "英文负向 prompt",
  "display_prompt_zh": "中文展示 prompt",
  "display_negative_prompt_zh": "中文展示负向 prompt",
  "style_notes": "风格备注"
}
```

### 最终生图输入

代码里真正发给图像模型的，不是纯 LLM 输出，而是：

```text
final_image_prompt_en =
  getShotCharacterTokens
  + llmImagePrompt
  + continuity tokens
  + camera keywords
  + styleBase.lighting
  + styleBase.quality
```

负面词最终为：

```text
llmNegativePrompt + styleBase.negative
```

### fallback 版本

如果 LLM 失败，会退到：

```text
scene {scene}
action {action}
emotion {emotion}
{continuity tokens}
{camera keyword}
single cinematic frame, clear subject focus
{lighting}
{quality}
```

## 4. 一致性 Checker

来源：`src/llm/prompts/consistencyCheck.js`

核心内容：

- 审核 AI 生成图中的角色外观一致性
- 关注脸、发型、服装、体型
- 10 分满分
- 明确标注身份锚点漂移

### User Prompt

```text

{characterCard.visualDescription}

```

## 9. Seedance Prompt Agent

来源：`src/agents/seedancePromptAgent.js`

这是当前单镜头 / sequence / bridge 体系里最关键的结构化 prompt 层。

### 9.1 Shot Generation Pack

最终 pack 包含：

- `shot_goal`
- `entry_state`
- `exit_state`
- `timecoded_beats`
- `camera_plan`
- `actor_blocking`
- `space_anchor`
- `character_locks`
- `environment_locks`
- `reference_stack`
- `negative_rules`
- `quality_target`

### 9.2 Seedance Prompt Blocks

最终会组装成这些 block：

```text
cinematic_intent: 导演意图或场景目标
shot_goal: 镜头目标
subject_action: 主题动作 + primary beat
scene_environment: 场景与风格
cinematography: 机位 / 景别 / 运镜 / 视角
reference_binding: 参考图绑定
entry_exit: entry / exit 状态
timecoded_beats: 时间轴动作节拍
camera_plan: coverage / framing / move
blocking: 人物调度
continuity_locks: 连贯性锁
negative_rules: 负面规则
quality_target: 质量目标
```

### 9.3 最终发给 Seedance 的 prompt

如果 `seedancePromptBlocks` 存在，真正给 provider 的文本是把这些 block 按固定顺序拼成英文：

```text
subject and action: ...
scene and style: ...
camera and timing: ...
reference binding: ...
entry anchor: ...
exit anchor: ...
continuity locks: ...
hard continuity rules: ...
```

然后再做 `ensureEnglishPrompt(...)`。

### 9.4 没有 blocks 时的 fallback prompt

会退回到：

```text
subject and action: visualGoal / sequenceGoal / sequenceContextSummary / sequence hint
scene and style: location / scene goal / dramatic question / continuity fallback
camera and timing: moveType / framing / camera flow / audio beat hints
reference binding: reference tier + reference assets
entry anchor: entryConstraint
exit anchor: exitConstraint
continuity locks: continuityTargets
hard continuity rules: hardContinuityRules
```

### 9.5 统一 provider client 的实际请求体

Seedance provider 最终收到的是：

- `content[0]`: 上述文本 prompt
- `content[1..n]`: 参考图 / 参考视频
- `ratio`
- `duration`
- `generate_audio = false`
- `watermark = false`

## 10. Preflight QA 重写

来源：`src/agents/preflightQaAgent.js`

当 QA 判定有风险时，会追加这些重写 block：

```text
repair_brief: fix before motion escalation: ...
repair_directives: ...
story_coherence_guard: keep one readable dramatic action...
```

同时也会强制补：

```text
continuity_locks: preserve geography, preserve facing direction, keep entry and exit readable
negative_rules: avoid axis break, avoid identity drift, avoid overactive camera
preflight_rewrite: favor restrained camera, simplify motion, and prioritize spatial readability over spectacle
```

来源：`src/agents/bridgeShotRouter.js`


### 负面词

```text

```

## 13. Bridge Clip Generator

来源：`src/agents/bridgeClipGenerator.js`

bridge clip 最终传给 provider 的 `visualGoal`，其实就是：

```text
bridgePackage.promptDirectives.join('. ')
```

所以 bridge 的最终文本输入，本质上就是 `promptDirectives`。

## 结论

当前项目里，真正有“自然语言 prompt”的主要是：

- 角色建档
- 角色三视图
- 分镜图 Prompt Engineer
- 一致性 Checker
- Seedance prompt blocks / fallback prompt
- Bridge directives

其余步骤大多已经是结构化 pack，不再靠一整段 prompt 文本驱动。
